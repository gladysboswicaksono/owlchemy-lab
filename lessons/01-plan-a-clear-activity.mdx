## Start with the task

Choose a workplace task before choosing the format of your activity. A format picked first tends to produce a quiz about whatever was on the slides.

{/* A Callout sets one message apart. type can be note, tip or warning.
    Try changing tip to note, save, and watch the colour, icon and label
    change together. */}

<Callout type="tip">
  Make the outcome observable. Describe something the learner can do, and
  that a colleague could watch them do.
</Callout>

## Compare two outcomes

The same topic can be written as something to know or something to do. Only one of them tells you what to build.

{/* A Comparison holds exactly two ComparisonItem blocks. Each needs a
    title (the card heading) and a token (the small label above it).
    Delete one card and save to see the error message, then undo. */}

<Comparison label="Two ways to write an outcome">
  <ComparisonItem title="Understand the refund policy" token="Hard to check">
    - Nobody can watch a person understand.
    - Any activity seems to fit, so the choice is a guess.
    - Success ends up meaning "they clicked through to the end".
  </ComparisonItem>
  <ComparisonItem title="Process a refund for a damaged order" token="Observable">
    - A colleague can watch it happen.
    - The activity is the task itself, with lower stakes.
    - Success is a refund that reaches the customer.
  </ComparisonItem>
</Comparison>

## Write it down

Three lines are enough for a brief. If you cannot fill in the second one, the task is still too vague to design for.

{/* Three backticks open and close a code block. The word after the opening
    backticks names the language, which sets the label and the colours.
    The Copy button is added for you. */}

```yaml
task: Process a refund for a damaged order
evidence: The refund shows in the order history within one working day
practice: Two sample orders, one with a missing receipt
```

{/* Information is for background a learner can skip. The title is yours
    to write. */}

<Information title="Why evidence comes second">
  Naming the evidence before designing the practice stops you building an
  activity you cannot assess. The practice then has one job: produce that
  evidence.
</Information>
